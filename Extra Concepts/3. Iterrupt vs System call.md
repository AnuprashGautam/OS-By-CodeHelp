## 🧠 Basic Idea

Both **interrupts** and **system calls** are ways to **communicate with the operating system (OS)** —
but they happen in **different situations** and for **different reasons**.

---

## ⚡ Analogy: “A Restaurant Kitchen”

Imagine you’re at a **restaurant** 🍽️

There’s a **customer (user program)**,
a **waiter (operating system)**,
and a **chef (hardware)**.

Now let’s see how **interrupts** and **system calls** fit in:

---

### 🔔 **Interrupt = Emergency Bell**

When something *unexpected* happens — like a customer drops a glass —
the **chef rings a bell** 🔔 to get the waiter’s attention.
The waiter (OS) immediately stops what they were doing and goes to handle it.

💡 In computers:

* Interrupt = a **signal** from **hardware** or **software** telling the OS something needs attention.
* Example: Keyboard input, mouse click, or a timer alert.

🧩 It’s like:

> “Hey OS! Stop for a second — something important just happened!”

---

### 📞 **System Call = Customer Request**

Now suppose a customer wants food 🍝.
They **call the waiter** and say,

> “Please bring me a pizza.”

The waiter goes to the chef and gets it done —
the customer doesn’t enter the kitchen directly.

💡 In computers:

* System call = a **request** made by a **user program** to the **OS** for some service.
* Example: Opening a file, writing to disk, creating a new process.

🧩 It’s like:

> “Hey OS! I want to do something that only you can do safely.”

---

## ⚙️ How They Work (in short)

| Step | Interrupt                        | System Call                                        |
| ---- | -------------------------------- | -------------------------------------------------- |
| 1️⃣  | Event occurs (e.g., key pressed) | Program calls a library function (e.g., `write()`) |
| 2️⃣  | Hardware sends signal to CPU     | Function triggers a software interrupt             |
| 3️⃣  | CPU pauses current task          | CPU switches to kernel mode                        |
| 4️⃣  | OS runs interrupt handler        | OS executes the requested service                  |
| 5️⃣  | OS returns control to program    | OS returns result to program                       |

---

## 🔍 Clear Difference

| Feature                 | **Interrupt**                         | **System Call**               |
| ----------------------- | ------------------------------------- | ----------------------------- |
| **Who triggers it?**    | Hardware or software automatically    | User program intentionally    |
| **When does it occur?** | Unpredictably (asynchronous)          | Predictably (synchronous)     |
| **Purpose**             | To handle urgent or unexpected events | To request OS services        |
| **Example**             | Keyboard press, disk ready            | `read()`, `write()`, `fork()` |
| **Type of control**     | External event control                | User-controlled               |
| **Direction**           | Hardware → OS                         | Program → OS                  |

---

## 🧩 Summary in One Line

> 🪄 **Interrupt** = “Something just happened! Handle it now.”
> ☎️ **System Call** = “Please do this for me.”
